SECURITY RESEARCH

Subdomain Takeover — Proof of Concept

This is NOT a NASA website. It is a benign proof-of-concept page hosted on an independent GitHub Pages site. It contains no NASA content, no credential prompts, no scripts, and no tracking. It exists solely to prove that a dangling CNAME on beta.science.nasa.gov can be pointed at third-party infrastructure by an unauthorized party.

Affected hostnamebeta.science.nasa.gov
CNAME targetnasa-smd.go-vip.net
ClassDangling CNAME / subdomain takeover (unclaimed provider site)
ProgramNASA Vulnerability Disclosure Program
Report tohttps://bugcrowd.com/engagements/nasa-vdp
Requested2026-11-08

How to reproduce

$ dig +short CNAME beta.science.nasa.gov
nasa-smd.go-vip.net.

$ dig +short A beta.science.nasa.gov
nasa-smd.go-vip.net.
192.0.66.125

$ curl -skI https://beta.science.nasa.gov/ | head -3
HTTP/2 404
server: nginx

$ curl -sk https://nasa-smd.go-vip.net/ | head -3
404 Not Found
404 Not Found
nginx

Why this is a takeover

nasa-smd.go-vip.net returns a bare nginx 404 Not Found page that is byte-for-byte identical to random unclaimed hostnames on the same platform, while every provisioned NASA site on that platform returns the provider's branded “Site not found” page or live content:

$ curl -sk https://nasa-smd.go-vip.net/        | head -1
404 Not Found
$ curl -sk https://nasa-gov.go-vip.net/ | head -1
Site not found
$ curl -sk https://nasa-hc.go-vip.net/  | head -1
Homepage | NASA Home & City
$ curl -sk https://nasa-tv.go-vip.net/  | head -1
Home | NASA+

The absence of the branded page means no site is provisioned for this hostname on the provider platform, so the hostname is available for registration by an unauthorized party.

Remediation

  1. Remove the CNAME record for beta.science.nasa.gov, or
  2. Re-provision the nasa-smd.go-vip.net site on the provider platform (so the platform returns its branded response again), and
  3. Audit the remaining *.nasa.gov CNAME records for the same condition — see the accompanying report for the full list.

No NASA systems were accessed, no data was collected, no credentials were requested, and the provider site was not registered. This page proves the vulnerability class only.
